# План эволюции данных (согласован 25.08.2026)

Итог архитектурного разбора (10 агентов: 4 линзы инвентаризации, 3 конкурирующих
проекта, 3 судьи с перепроверкой по коду; полные отчёты — в сессии владельца).
Каркас — **точечная эволюция по готовым образцам** самой системы: IMSA-снапшот
(нормализованный JSON с конвертом), `FiaEvent` (одна схема на три серии),
`f1/teams/<y>.json` (экран одним файлом), `overrides/calendar.json` (курируемое —
данные, не релиз). Большой «канонический датасет» одним заходом не строим;
элементы конкурирующих проектов (фикстуры контракта, nullable-ref, identities
по сезонам, pins) забраны амендментами.

**Ключевое окно: приложение не опубликовано** (0.6.5.x, App Store в будущем
времени). Контракты сейчас ломаются почти бесплатно; день первой публикации —
глобальная точка невозврата, после него опубликованные пути замораживаются.
Вся контракто-образующая работа (WEC-JSON, зачёты, календарь, событие) — до неё.

## Целевая картина

Три слоя с чёткими ролями:

- **Кухня** — сырые зеркала (jolpica, openf1, fiawec HTML, Al Kamel). Читают
  только продьюсеры; из публичного контракта сырьё уходит. Перед публикацией
  приложения кухня уезжает в приватный репозиторий (см. чеклист внизу).
- **Знания** — `refs/` (карта сущностей с per-source алиасами) + курируемые
  каталоги. Обновление — правка данных, не релиз приложения.
- **Витрина** — публичный контракт: календарь / события / зачёты / агрегаты
  экранов + health, в едином формате конверта. Это и есть «качественный
  датасет»: происхождение, накопление, свежесть, совместимость.

Приложение — тонкий клиент: 3–5 запросов на экран, декод и рендер; клиентские
мерджи умирают или становятся live-фолбэками; вкомпилированные словари и
каталоги — офлайн-дно каскада НАВСЕГДА (seed-механизма в приложении нет,
и городить его не нужно). Мимо витрины ходит только live-оверлей активной
сессии уик-энда — и отбрасывается, как только витрина догнала.

## Сквозные правила для всего нового

1. Конверт `writeJSONWithEnvelope` + явный `schemaVersion`; `frozen: true` у
   завершённого (клиенту — «кэшируй навсегда»). Эволюция схем только аддитивная.
2. **Nullable ref + display-строка рядом** в каждой строке фактов: незаматченная
   сущность деградирует до сегодняшнего поведения, а не ломает экран.
   Fail-open для фактов, fail-closed для реестра (реестр только накапливается).
3. Каждый новый продьюсер наследует: накопление (`mergeFiaEvent`-паттерн),
   fail-closed для агрегатов, freeze/write-once для истории, бюджет свежести
   в реестре `lib/producers.ts`.
4. **Контракт-фикстуры**: CI бэкенда экспортирует фикстуры схем →
   `OverlapTests/Fixtures/` — Swift-тесты декодят те же байты, что произвёл TS.
   Сегодняшнее «схемы держатся конвенцией» уходит.
5. Клиентские фолбэки помечаются `// FALLBACK until <версия>` + записью в
   KNOWN_ISSUES. Пока приложение не опубликовано — фолбэки убиваются быстро.
6. **Критерий материализации**: сшивает источники или стоит запросов → бэкенд;
   чистая функция над одним уже загруженным файлом → клиент. По нему дуэли и
   полки поиска остаются на клиенте, погода-прогноз остаётся live. Фиче
   понадобились данные вне экрана → она становится новым продьюсером.

### Фаза 2 — `refs/matching.json` (M) — ВЫПОЛНЕНА 26.08.2026 (приоритет у встроенных таблиц до обкатки)

Одна курируемая карта сущностей вместо ~25 алиас-таблиц в двух репозиториях:

- трассы: канонический слаг + per-source алиасы + **pins** — явная привязка
  аномалий к (season, round) (класс «Bahrain GP in Malaysia» / «Bahrain
  Tests → R4»);
- эндуранс-команды: **identities по сезонам** (кейс JOTA: winsHere не должен
  обнуляться ребрендом), бренд, связь серий;
- F1-команды: id + исторические id (`mclaren-ford`), имена OpenF1, база, цвета;
- исключения имён пилотов (частицы, суффиксы, «Sørensen»).

Наполнение — аудит-скриптом слияния существующих таблиц (не перепечаткой);
скрипт заодно вскроет расхождения класса DATA-GAPS. Продьюсер-валидатор
fail-loud на дубли/конфликты. Swift-словари остаются фолбэком с warning при
расхождении. Никакого авто-append в курируемые файлы; сезонный ритуал —
скрипт, генерящий PR перед сезоном.

Итог выполнения: карта (39 трасс × 9 пространств алиасов, 5 pins, 12 команд
F1, 7 эндуранс-команд, исключения имён, страны) + валидатор тестом в CI +
4 матчера и winnersbuild читают карту (встроенная побеждает, warning при
расхождении; паритет 197 сравнений бит-в-бит) + клиентский паритет-тест
RefsParityTests с фикстурой. Аудит расхождений — scripts/refs-audit.md.
ОТКРЫТО к следующим решениям: перещёлк приоритета на карту после обкатки;
force-пересборка winners (11 строк IMSA, «Corvette by Pratt Miller» 1→6);
правки-кандидаты карты (fiaDocPrefix barcelona-catalunya, «sao» interlagos,
D1-инверсия Lusail); pinFor при season=undefined считает сезонные pins
подходящими (недостижимо в проде, помнить при новых потребителях).

### Фаза 3 — WEC: JSON вместо HTML (L, три жёстко упорядоченных шага)

Крупнейшая боль: 25 МБ HTML (полезная плотность 5–10%), ~700 строк regex на
устройстве, 44% прироста git-истории, единственный несвязанный TS↔Swift-стык
(независимая нумерация раундов). Формат — копия IMSA.

- 3a `wec/<y>/index.json` + `standings.json`: round присвоен бэкендом
  (нумерация одноместная), экипажи слиты, реальные wins, флаги через refs. M.
  — ВЫПОЛНЕНО 26.08.2026. Отступления: флаги остались клиентской картой
  (не связывать репо через refs); 2025/standings.json не существует честно
  (источник несёт только текущий сезон); wins настоящие из highlights
  classWinners с откатом на прокси при ненадёжности. Клиент: −98.7% байт
  холодного WEC-стека (12 GET/4.5 МБ → 3 GET/61 КБ), HTML — фолбэк.
- 3b `wec/<y>/<NN>_<slug>.json` — сессии события в форме IMSA, Hyperpole
  как отдельная фаза, экипажи разрезолвлены. Честно: парсинг таблиц в TS
  отсутствует (`fiawecsite.ts` — только helpers), портировать ~520 строк
  Swift-регексов. M–L.
- 3c Обкатка ≥1 цикл на паритет-фикстурах (JSON бэкенда против вывода
  Swift-парсеров на сохранённых событиях) → удаление ~700 строк парсеров.
  HTML-зеркало остаётся кухней. S + календарное время.

### Фаза 5 — трассы и историческая погода (M)

- 5.1 Геометрия/факты/SC-каталог из Swift-кода → курируемые данные бэка.
  Разовая выверка пяти задокументированных расхождений (DATA-GAPS.md),
  однозначные имена полей (`elevationGain` ≠ `altitude` — конфликт Мехико).
  Вкомпилированное остаётся офлайн-дном.
- 5.2 `tracks/index.json`: конверт (единственный derived без него) +
  `winnerLaps`/`hours` по сериям (убирает WEC-пайплайн 1.2 МБ из деталки).
- 5.3 **Историческая погода** — блок `weather` в файле события, write-once
  после freeze: OpenF1 weather (F1 2023+), **статика FOM
  `livetiming.formula1.com/static/` (F1 2018–2021** — WeatherData.jsonStream,
  проверено живьём; 2022 в архиве отсутствует целиком, 2018 — только
  относительное время сессии), Al Kamel CSV (WEC/IMSA), Open-Meteo archive
  (остальное/старше). Прогноз остаётся live на клиенте. Открывает кейс
  «мастера дождя» из карты источников.
- 5.4 **Проактивный снапшот срезов статики FOM 2018–2021 в кухню** (погода,
  TimingAppData со стинтами/компаундами, RaceControlMessages, PitLaneTime):
  политика ретенции архива неизвестна, 2017 и 2022 уже отдают 403 — что не
  сняли, можем потерять. Парсеры — свои (код br-g/openf1 под CC BY-NC-SA,
  в наш пайплайн нельзя; форматы и факты не копирайтятся). S–M.

Кандидаты-продьюсеры из разведки 25.08 (после фазы 5, по мере надобности):
стинты/компаунды F1 2018+ (у Jolpica компаундов нет), машинный пересчёт
SC/VSC из RaceControlMessages 2018+ (снимает ручное курирование SC-каталога
и углубляет его), overtakes из DriverRaceInfo 2018+. Пит-тайминги: до 2024
только время в пит-лейне; раздельный stop_duration — 2025+. Запасной источник
результатов/гридов — api.formula1.com/v1 (публичный apiKey сайта). Правовой
статус статики FOM = тот же класс риска, что текущее зеркало OpenF1
(производные live timing без цепочки прав) — учитывать в пре-публикационном
аудите наравне.

### Фаза 6 — событие одним файлом (L; после фазы 3, формат обкатан на двух сериях)

`<series>/events/<s>_<r>.json`: структура уик-энда + протоколы с

`fastestLapWeekend` ≠ `fastestLapRace` (снимает семантическую коллизию;
умирает клиентский дубль `WeekendHighlights`). Этапно: сначала склейка
готовых derived, потом протоколы OpenF1, грид — последним.

## Пре-публикационный чеклист (вне миграции)

- **Репо-сплит**: кухня (сырые зеркала) — в приватный репозиторий, наружу
  только витрина. Единственный реальный механизм закрытия правового риска
  редистрибуции сырья (jolpica/openf1/fiawec HTML). Делается вместе с
  разбором блокера overlap-assets из аудита источников. M–L.
- Ревизия фолбэков: всё, что помечено `FALLBACK until`, либо умирает, либо
  получает осознанное продление.

погода-прогноз (live по определению), вёрстка колонок зачётов
(представление, не данные). Архив openf1 2023–2024 — хранится как архивный
вход будущих фич, приложением не читается, в витрину не публикуется.
