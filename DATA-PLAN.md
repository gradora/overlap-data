# План эволюции данных (согласован 25.08.2026)

Итог архитектурного разбора (10 агентов: 4 линзы инвентаризации, 3 конкурирующих
проекта, 3 судьи с перепроверкой по коду; полные отчёты — в сессии владельца).
Каркас — **точечная эволюция по готовым образцам** самой системы: IMSA-снапшот
(нормализованный JSON с конвертом), `FiaEvent` (одна схема на три серии),
`f1/teams/<y>.json` (экран одним файлом), `overrides/calendar.json` (курируемое —
данные, не релиз). Большой «канонический датасет» одним заходом не строим;
элементы конкурирующих проектов (фикстуры контракта, nullable-ref, identities
по сезонам, pins) забраны амендментами.

**Ключевое окно: приложение не опубликовано** (0.6.5.x, App Store в будущем
времени). Контракты сейчас ломаются почти бесплатно; день первой публикации —
глобальная точка невозврата, после него опубликованные пути замораживаются.
Вся контракто-образующая работа (WEC-JSON, зачёты, календарь, событие) — до неё.

## Целевая картина

Три слоя с чёткими ролями:

- **Кухня** — сырые зеркала (jolpica, openf1, факты fiawec (wec/facts), Al Kamel). Читают
  только продьюсеры; из публичного контракта сырьё уходит. Перед публикацией
  приложения кухня уезжает в приватный репозиторий (см. чеклист внизу).
- **Знания** — `refs/` (карта сущностей с per-source алиасами) + курируемые
  каталоги. Обновление — правка данных, не релиз приложения.
- **Витрина** — публичный контракт: календарь / события / зачёты / агрегаты
  экранов + health, в едином формате конверта. Это и есть «качественный
  датасет»: происхождение, накопление, свежесть, совместимость.

Приложение — тонкий клиент: 3–5 запросов на экран, декод и рендер; клиентские
мерджи умирают или становятся live-фолбэками; вкомпилированные словари и
каталоги — офлайн-дно каскада НАВСЕГДА (seed-механизма в приложении нет,
и городить его не нужно). Мимо витрины ходит только live-оверлей активной
сессии уик-энда — и отбрасывается, как только витрина догнала.

## Сквозные правила для всего нового

1. Конверт `writeJSONWithEnvelope` + явный `schemaVersion`; `frozen: true` у
   завершённого (клиенту — «кэшируй навсегда»). Эволюция схем только аддитивная.
2. **Nullable ref + display-строка рядом** в каждой строке фактов: незаматченная
   сущность деградирует до сегодняшнего поведения, а не ломает экран.
   Fail-open для фактов, fail-closed для реестра (реестр только накапливается).
3. Каждый новый продьюсер наследует: накопление (`mergeFiaEvent`-паттерн),
   fail-closed для агрегатов, freeze/write-once для истории, бюджет свежести
   в реестре `lib/producers.ts`.
4. **Контракт-фикстуры**: CI бэкенда экспортирует фикстуры схем →
   `OverlapTests/Fixtures/` — Swift-тесты декодят те же байты, что произвёл TS.
   Сегодняшнее «схемы держатся конвенцией» уходит.
5. Клиентские фолбэки помечаются `// FALLBACK until <версия>` + записью в
   KNOWN_ISSUES. Пока приложение не опубликовано — фолбэки убиваются быстро.
6. **Критерий материализации**: сшивает источники или стоит запросов → бэкенд;
   чистая функция над одним уже загруженным файлом → клиент. По нему дуэли и
   полки поиска остаются на клиенте, погода-прогноз остаётся live. Фиче
   понадобились данные вне экрана → она становится новым продьюсером.

  закончившейся сессии страницы в зеркале нет — клиент промахивался и брал
  свежий протокол прямо у источника. Проверено на боевых данных: у сыгранного
  этапа (raceId 4952) в зеркале все 9 страниц сессий, у предстоящего (4953) —
  только дропдаун. Живое окно давало свежесть в интервале «сессия опубликована
  → следующий прогон крона», а крон рваный (27.08: разрывы 4.6 ч и 10.25 ч при
  объявленном часовом). Дыра закрыта НА БЭКЕНДЕ, а не возвратом парсеров:
  новый продьюсер `weclive` + воркфлоу `weclive.yml` (`*/15` ежедневно, своя
  concurrency-группа) обновляет страницы ТОЛЬКО идущего этапа и пересобирает
  его файл; холостой прогон не касается сети вовсе, маркер свежести пишется
  днём. Честно: это НЕ паритет — потолок задержки стал каденсом weclive
  (по замеру fia.yml GitHub доставляет `*/15` раз в 20–35 минут) вместо
  мгновенной свежести на открытии экрана.
  Ещё две подтверждённые находки закрыты в клиенте: (1) stale-кэш теперь
  отдаётся при ЛЮБОЙ неудаче, включая недекодируемые свежие байты — прежнее
  «декод-фейл → nil» оправдывалось живым каскадом, а без него один
  недописанный index.json гасил бы все экраны событий при живой копии на
  диске; (2) джойн экипажей по номеру машины (единственный источник имён
  пилотов на архивных сезонах) покрыт тестом — мутант, зануляющий его,
  переживал весь прогон.
  ОТКРЫТО: пустое состояние «зачёта сезона ещё нет» для межсезонья (в январе
  2027 `wec/2027/standings.json` не появится, пока fiawec не переключит
  страницу).

ДОЧИНЕНО ПОСЛЕ СКЕПТИКОВ (8 находок, все с мутационной проверкой):
1. БЛОКЕР — отмена этапа посреди сезона морозила витрину НАВСЕГДА:

   ровно в том классе событий, ради которого фаза и завела `kind: cancelled`.
   Каждый час `kept-previous`, `F1_CALENDAR_FORCE` не спасал (он про freeze),
   клиент тихо уходил на живой мердж. Теперь пропажа confirmed сверяется
   ПОИМЁННО: оправдана, если на том же дне гонки стоит `cancelled`;
   необъяснённая — по-прежнему держит файл. Воспроизведено и проверено на

### Фаза 6 — событие одним файлом (L; после фазы 3, формат обкатан на двух сериях)

Разведка 28.08.2026 поправила формулировку фазы в двух местах — исходный
текст был неверен, а не неточен.

**Имя файла — `<series>/events/<id события витрины>.json`, НЕ `<s>_<r>`.**
Раунд не адресует события: сентинел `round: 0` — инвариант бэкенда, и в
календаре 2026 таких событий четыре (`f1-meeting-1304`, `1305`, `1282`,
`1283`) — все схлопнулись бы в один `2026_0.json`. Id витрины совпадает с
`CalendarItem.id` на клиенте посимвольно (`f1-2026-1`, `f1-meeting-1304`,
`f1-override-<дата>`), поэтому клиенту не нужна никакая проводка ключа —
ровно как у `f1/weather` сегодня. Схема `<s>_<r>` потребовала бы, наоборот,
нового поля через пять точек сборки `CalendarItem` и джойна по дате.

**Файл события — производная, а не замена.** Round-keyed семейства
`fia`/`winners`/`highlights`/`milestones` остаются: у них есть потребители
вне экрана события (экран поиска на клиенте; продьюсеры `f1beasts`,
`wecsnapshot` на бэкенде). Выигрыш «4–5 GET → один» верен для экрана
события, но не означает ретайра семейств.

**Погода — отдельным файлом, инлайна не будет.** Замер: `f1/weather` —
70 КБ в среднем, 224 КБ максимум против 7.3 КБ всех остальных derived
вместе; сегодня она грузится условно (только у прошедшего события), а веер
вех на экране поиска превратился бы из 240 байт в десятки килобайт.
