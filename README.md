# overlap-data

Снапшот-бэкенд данных приложения **Overlap** (F1 / WEC / IMSA): GitHub Actions
по расписанию тянет источники, кладёт ответы и derived-карточки в `data/`,
приложение читает их mirror-first с `raw.githubusercontent.com` (фолбэк —
живой источник). Зачем: прошедшие результаты доступны независимо от состояния
источников и того, открывал ли пользователь приложение; источники разгружены.

## Архитектура

```
Jolpica ─┐                       ┌─ data/f1/jolpica/   (зеркало, + пер-раундовые слайсы)
OpenF1 ──┤                       ├─ data/f1/openf1/    (зеркало, история 2023+)
fiawec ──┤  src/producers/* ────►├─ data/wec/fiawec/   (зеркало HTML, нормализовано)
Al Kamel ┤  (cron, см. ниже)     ├─ data/{f1,wec,imsa}/{fia,winners,highlights}/
fia.com ─┤                       ├─ data/f1/{milestones,beasts,records,history}/
enwiki ──┘                       ├─ data/imsa/<year>/  (снапшот этапов)
                                 ├─ data/f1/calendar/<year>.json (смёрженный календарь)
                                 ├─ data/tracks/index.json
                                 └─ data/health.json   (heartbeat + статусы)
```

- `src/lib/` — общий код: `mirror` (slug-контракт со Swift! см. data/README),
  `http` (UA+retry), `sources`, `slug`, `env`, `freeze` (два окна оседания: 7д
  по умолчанию и 14д — срок права FIA на пересмотр — у трёх стюардских
  продьюсеров `fia`/`wecfia`/`imsafia`, чьи файлы накапливаются слиянием),
  `season`, `schedule` (курируемый календарь IMSA),
  `alkamel*`, `fiawecsite`.
- `src/producers/` — 19 продьюсеров-entrypoint'ов (по одному npm-скрипту),
  друг друга не импортируют: общий код — только через lib (`fiadocs` — парс-ядро
  документов стюардов, `winnersbuild` — сборщики прошлых победителей).
- `data/f1/fia/<season>_<round>.json` — файл раунда ТОЛЬКО НАКАПЛИВАЕТСЯ: прогон
  сливается с уже собранным (`mergeFiaEvent`), а не перезаписывает его. Решение,
  чей PDF в этом прогоне не дался, остаётся из файла; свежий разбор побеждает
  для того же номера документа; решётка не теряется и не откатывается
  final → provisional. Автоматических удалений НЕТ вовсе: настоящих отзывов
  документа за всю историю репозитория не было ни одного (все 220 исчезновений
  решения — следы прежнего бага с перезаписью), а урезанный листинг fia.com
  (3 строки из 19) снёс бы 16 собранных решений. Документ, пропавший со
  страницы, остаётся в файле и логируется `::warning::` — разбирается глазами;
  выкинуть отозванный документ можно ТОЛЬКО удалив файл раунда и прогнав
  продьюсер заново (`FIA_FORCE=1` тут не помощник: он перекачивает документы, а
  слияние всё равно безусловно сохраняет всё, что уже лежало в файле).
  Неполный ПЕРВЫЙ сбор раунда не публикуется вовсе: пока файла нет, спасать
  слиянию нечего, а записанный огрызок закрыл бы раунду дорогу назад — бэкфилл
  ищет ровно отсутствующие файлы, и замороженный раунд больше не обработается.
  Раз файл накапливается — прогон и КАЧАЕТ только недостающее: документ, уже
  разобранный в файле (тот же url + publishedAt + «Corrected» в заголовке), не
  перекачивается; между закачками PDF — пауза 200 мс. Обходы пропуска два:
  `FIA_FORCE=1` (доходит и до замороженных раундов, отсюда рецепт полной
  пересборки `FIA_FORCE=1 FIA_BACKFILL=99 npm run fia`) и бамп
  `PENALTY_PARSER_VERSION` — иначе правка классификатора не дошла бы до уже
  собранных решений. Версия парсера пишется В КАЖДУЮ ЗАПИСЬ (`parser` у штрафа
  и у решётки), а не в файл: прогресс подокументный, одна осечка не откатывает
  весь раунд к «качаем всё заново». Грид-штраф «на следующую гонку» переносится
  в следующий раунд, только если тот стартует ПОЗЖЕ публикации вердикта (на
  back-to-back поздний вердикт иначе лёг бы на решётку уже прошедшей гонки).
  Окно оседания у раунда — 14 дней (`isStewardsFrozen`) у всех трёх стюардских
  продьюсеров: их файлы накапливаются слиянием (`mergeFiaEvent` у F1,
  `mergeStewardsPenalties` у WEC/IMSA), и осечка прогона ничего не стирает.
- `data/f1/overrides/calendar.json` — РУЧНАЯ ручка: завод события до появления
  в источниках (кейс Sepang), приложение показывает с бейджем TBC и само
  дедуплицирует после публикации. Записи продьюсеры НЕ создают и не правят;
  единственная автоматика — GC отживших (`f1overrides`): запись убирается,
  когда конец её дня гонки + грейс 7 дней позади («прошло») или когда этап
  с тем же `circuitId` того же сезона появился в jolpica на дне вне окна
  дедупа −2…+3 («переехало» — иначе на старой дате воскрес бы фантом-дубль).
  Пока событие не прошло и не переехало, запись живёт погашенной дедупом —
  страховка от отката источника. Поле `circuitId` (jolpica id) опционально,
  без него правило «переехало» для записи выключено.
  Запись применяется к своему сезону по полю `season` — в том числе к
  СЛЕДУЮЩЕМУ (ради межсезонья ручка и заведена); к закрытому сезону не
  применяется. Запись, не доставшаяся ни одному собранному сезону (опечатка в
  годе, год без зеркала расписания), проговаривается в логе прогона.
  Битый JSON валит прогон (файл ручной — молча затирать нельзя), но ПОСЛЕ
  сборки витрины: календарь всех сезонов из-за лишней запятой не замирает,
  теряется только курируемый слой.
- `data/f1/calendar/<год>.json` — ВИТРИНА календаря (фаза 4 DATA-PLAN):
  расписание jolpica, смёрженное с результатами/спринтами по ПАРЕ
  (season, round), плюс оверлей митингов OpenF1 (тесты, отмены, этапы, которых
  в jolpica ещё нет — дедуп ПО ДАТЕ, не по имени) плюс курируемый слой выше.
  Собирается внутри прогона `f1overrides` — единственного шага, который идёт
  ПОСЛЕ всех трёх входов в одном прогоне и после GC ручки; сети в сборке нет.
  Охват — сезоны, которые показывает приложение (2025+ и N+1, как только у
  него появилось зеркало расписания). Замороженный сезон не пересобирается
  (`F1_CALENDAR_FORCE=1` — перебить).
  Предохранитель записи (прежний файл не трогаем): пропало зеркало, схлопнулись
  гонки, потерялась привязка к митингам, не прошёл кросс-чек ключей. Отмена
  этапа предохранителем НЕ считается: jolpica снимает отменённый раунд из
  расписания, и confirmed-этапов законно становится меньше — пропажу оправдывает
  событие `cancelled` на том же дне гонки, необъяснённая пропажа держит файл.
  Для сезона N+1 зеркало митингов OpenF1 обновляет ежесуточный шаг «Сезон N+1»
  (режим «future» — только листинг): тесты и отмены следующего года есть
  только там.
- `data/f1/records/catalog.json` — РУЧНОЙ каталог all-time рекордов
  (held/chases) для продьюсера f1records.

## Workflows

| Workflow | Расписание | Что | Гейт |
|---|---|---|---|
| `snapshot.yml` | каждый час (`17 * * * *`) | 20 продьюсеров + health | outcome всех шагов + свежесть по реестру |
| `fia.yml` | `*/15` Пт–Вс | только штрафы FIA (своя concurrency-group — не дропается за snapshot) | exit-code |
| `tracks.yml` | Пн 04:00 | справочник трасс из англ-вики | exit-code + свежесть через маркер |
| `ci.yml` | push/PR | typecheck + tests | — |

Коммит/пуш — общий composite action `.github/actions/commit-push` (5 попыток
с rebase). Алерт: любой упавший продьюсер валит job → письмо владельцу;
исключения-толерантности: OpenF1 401 в лайв-сессию, records при пустом сезоне.

### Свежесть данных

`outcome` шага отвечает только на «крон сходил и шаг не упал». Продьюсера,
которого забыли вписать в воркфлоу, он не видит по построению — так `f1teams`
простоял 17 суток, и заметил это владелец, а не система. Второй сигнал:

- **`src/lib/producers.ts`** — реестр всех продьюсеров с бюджетом «сколько
  суток допустимо без УСПЕШНОГО прогона». Объявляется НЕЗАВИСИМО от проводки:
  нет шага в воркфлоу → отметку никто не обновляет → через бюджет тревога.
  Новый продьюсер добавляется СЮДА, а не только в `snapshot.yml`.
- **`data/health.json`** — `lastSuccess` (день последнего успеха по каждому,
  переносится между прогонами), `firstSeen` (кто не отработал ни разу; пусто —
  норма), `stale` (кто вышел за бюджет; пусто — норма). Только дни UTC: метка
  точнее суток превратила бы часовой крон в коммит-спам и убила бы
  heartbeat-дисциплину.
- **Гейт «Проверка свежести данных»** в `snapshot.yml` — ПОСЛЕ шага коммита,
  валит job на непустом `stale`.
- Продьюсер из чужого воркфлоу (`tracks`) оставляет маркер
  `data/tracks/_health.json`, который health.ts читает на ближайшем прогоне.

Бюджеты: ежечасные — 3 суток, `tracks` — 14 (недельный ритм плюс один
потерянный понедельник). Чего сигнал НЕ ловит: продьюсера, который штатно
выходит нулём, ничего не записав (fail-open) — для этого отдельный счётчик,
см. `health.blocked`.

## Операторские ручки (env)

Семантика едина (`src/lib/env.ts`): флаг включён ⇔ значение ровно `1`.

| Ручка | Дефолт | Что |
|---|---|---|
| `SEASON` | текущий год | сезон прогона; прошлый год у openf1 = historic-бэкфилл |
| `FIA_BACKFILL` / `WEC_FIA_BACKFILL` / `IMSA_FIA_BACKFILL` | 2 / 1 / 1 | сколько прошлых этапов доскрейпить |
| `FIA_FORCE` / `WEC_FIA_FORCE` / `IMSA_FIA_FORCE` | — | пересобрать даже замороженные |
| `WEC_HL_FORCE` / `IMSA_HL_FORCE` | — | то же для хайлайтов |
| `WEC_WINNERS_BACKFILL` / `IMSA_WINNERS_BACKFILL` | 1 | глубина бэкфилла победителей |
| `TRACKS_ONLY=slug,slug` | — | ТОЛЬКО отладка: пишет index из перечисленных — коммитить нельзя |

## Данные

Конвенции имён файлов и slug-контракт — `data/README.md`. Derived-семейства
несут конверт `{schemaVersion, generatedAt}` (метка меняется только с данными).
Сезонное обслуживание — `SEASON-CHECKLIST.md`.
