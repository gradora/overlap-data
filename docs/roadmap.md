  именем и чистой историей несёт только витрину; кроны — на Railway с
  работающим алертингом; GH Actions выключены; старые SHA публичного
  репо отдают 404 (уходит и хвост «сырьё в git-истории»).
- Лайв-поток определён: записи фида разобраны, форма лайв-заготовки
  зафиксирована, рекордер — штатный инструмент.
- Операционка задокументирована: ритуалы, бюджеты свежести, процедуры
  бампов (уже в docs/f1-kitchen-plan.md и railway.md).

## Этапы (порядок = рекомендуемый)

### 3. Обкатка Мадрида (11–13.09, пассивно) + пост-этапные ритуалы
Первый живой уик-энд f1live на фактах И на контракте D-лайт: смотреть
каденс, предполёт, pit-heal, чеканку eventKey живого этапа. После
этапа: `npm run f1pitawards`, preferredTire Мадрида, brands.json.

### 3a. Пострейс-канал PitStopSeries — чинит питы навсегда (первый по ценности)
Находка разбора Монцы: `PitLaneTimeCollection` live-фида = время в
пит-лейне, а stationary в live НЕ отдаётся — зато **статика FOM
`<Path из SessionInfo>/PitStopSeries.jsonStream` отдаёт настоящие
stationary всех стопов** (200 без auth; проверено 2025–2026, 2024 —
403 именно на этом топике). Это лечит дыру openf1 `stop_duration`
(null с Венгрии-2026) и ретроспективно за 2025–2026, без записи гонок.
Оговорки: с раннеров GH — 403 (класс fomstatic, продьюсер ручной либо
проверить egress Railway); файл не 100 %-полон (стоп OCO в Монце
отсутствовал) — обязателен кросс-чек с PitLaneTimeCollection.
Заменяет ручной DHL-ритуал `f1pitawards`.

### 3b. Стинты: круги и возраст резины
`TyreStintSeries` даёт new/used, возраст при установке и границы кругов
— у нас в факте только компаунды (последовательности сошлись 1:1, так
что источник надёжен). Расширение стинт-факта + стинт-чарт в S-полке
получает данные. Источник — та же статика/фид.

### 3c. Фикс overtake-бага витрины рейс-контрола
Режим обгона 2026 (OVERTAKE ENABLED/DISABLED) мапится в `kind:"drs"` —
семантически неверно и мешает добавлять новые kind. Починка = правка
`classifyRaceControl` + бамп `RACECONTROL_PARSER_VERSION` по РУЧНОЙ
4-шаговой процедуре (гашение кронов → пересъём → конвертер → один
коммит). Заодно: RC-фид несёт точные UTC, которых у openf1 нет вовсе —
кандидат на расширение семейства `racecontrol` полем времени.

### 4. Витрина архива 2023–24 — смерть каскада openf1 (крупный, ~дни)
Хвост фазы 6: календарь v2 и файлы событий для сезонов 2023–2024,
чтобы клиентский каскад (meetings/sessions/drivers/session_result/
stints/race_control из f1/openf1) умер целиком. Разведка → дизайн →
конвертация по образцу сделанных этапов. Это ЕДИНСТВЕННОЕ, что держит
clientReads у заготовки f1/openf1 и числовые ключи openf1 в контракте.

### 5. Клиентский срез 0.6.7 (после Мадрида — цикл обкатки есть)
Снять остатки: jolpica-ветки промаха current*, цепочки OpenF1 экрана
события (после этапа 4 они мертвы по построению), прямой Open-Meteo +
словарь координат + makeTypical, каскад архива → витрина 2023–24.
Сюда же: решение по глубокому архиву погоды (WEC 2011+ — бэкфилл или

Оговорка N+1: фолбэк loadSessions для событий без файла живёт до
