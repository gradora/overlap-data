## 1. Заготовка openf1 (30.4 МБ, 1996 файлов → ~10 МБ)

Все 8 семейств имеют читателей — удалять нечего, режем ФОРМУ:

- **Класс А** (meetings, sessions, drivers, session_result, stints, pit):
  тот же JSON-массив строк, но только keep-поля реестра. Читатели сборки
  И клиента не меняются вовсе (обязательные поля Swift-декодеров входят в
  keep: session_type, session_key — проверено по OpenF1Models.swift).
- **Класс Б** (weather 11.2 МБ → колоночный факт ~2.8 МБ; race_control
  6.6 МБ → классифицированные строки ~1.5 МБ): нормализация/классификация
  переезжает с чтения на запись. race_control — вариант R1: файл остаётся
  МАССИВОМ (клиентский каскад 2023–24 жив), строки несут факт-ключи +
  legacy-ключи, message — НАШ синтез из фактов (порт RaceControlSource.
  event(from:)), вербатим FIA не сохраняется.
- Каталог и имена файлов (mirrorSlug) НЕ меняются — сшивка sourceIds,
  клиентская адресация и GC живут на этой форме; возврат сырья ловится
  ФОРМОЙ (белый список ключей), а не именем.

**Амендменты судей (обязательные, внесены в спеку):**
1. Версия парсера race_control — ПЕР-СТРОЧНЫМ ключом (Swift игнорирует
   лишние ключи), не только в семейном манифесте: иначе частичная
   миграция после бампа непредставима.
2. Правило сериализации класса А: писатель кладёт ВСЕ keep-ключи всегда
   (отсутствующие у источника — явным null); оракул сравнивает точное
   равенство множеств по ВСЕМ строкам, не row[0]. Пропажа ключа у
   источника не порождает вечную перекачку; сплошной null — warning.
3. Переходная семантика: оракул и walk-тест гейтятся по манифесту
   `_extractor` — неконвертированное семейство живёт по existsSync.
   Приёмка этапов 0–1: 0 сетевых запросов по замороженному архиву.
4. Предполёт — ТРЕВОГА, не гейт коммита: throw красит шаг (в snapshot.yml
   и f1live.yml openf1 стоит с continue-on-error, коммит — if: always()),
   гейт продьюсеров валит job → письмо владельцу, а данные прогона
   ПУБЛИКУЮТСЯ. Формула «exit 1 → коммита нет» была ложью в CI; жёсткие
   гейты «дальше нельзя» — в конвертерах этапов 1–3 (локальный запуск
   при гашёных кронах). Дыры = ОТСУТСТВУЮЩИЕ файлы (staleness — не дыра,
   а очередь добора). Бейслайн — НЕ скаляр (симуляцией доказано
   отравление пропажей листинга), а по-митинговая карта дыр
   (meetingKey → n) плюс счёт замороженных митингов по годам в
   `_extractor`. Тревоги: дыры митинга сверх карты; митинг из карты
   пропал из матрицы / потерял листинг; год усох по числу замороженных
   (битый meetings_year_*). Автоснижение — только по-митингово при
   реальном закрытии дыр; новые «вечные» дыры принимаются явно —
   OPENF1_ACCEPT_HOLES=1, осознанный разовый локальный прогон. Замер
   07.09.2026: бейслайн 21 дыра — 7 живых Японии-2026
   (session_result/stints), 13 pit 2023–25 и 1 session_result
   квалификации Бельгии-2023; race_control — 0.
5. Добор (backfillLateHandles): скип по оракулу, не existsSync; wanted
   расширить до session_result/stints (живые дыры Японии-2026);
   mirrorIfMissing (historic) — тоже через оракул. drivers митинга — В
   матрице полноты (у него читатель entrylist). Кап добора (40 GET) —
   только в кроновом пути; BACKFILL=late идёт БЕЗ капа по умолчанию
   (ручной прогон при гашёных кронах), опция оператора —
   BACKFILL_GET_CAP=N.
6. Сторож шаблонов race_control — В ПРЕДПОЛЁТЕ писателя, не только CI
   (вербатим не должен закоммититься даже одним прогоном).
7. Слепок в приват освежать перед КАЖДЫМ уничтожающим конвертером
   (этапы 1, 2, 3), не только перед первым.
8. Формулировка честнее: правовой блокер openf1 этим шагом СУЖЕН, не
   снят — полное сырьё остаётся в git-истории до фазы C, схема/ключи
   openf1 в заготовке сохранены осознанно (вопрос №3 владельцу).
9. Отменённые митинги (Эмилия-2023, Бахрейн и Сауди-2026) исключены из
   матрицы полноты и из целей добора ЦЕЛИКОМ: источник их сессий не
   отдаёт никогда, 64 «вечные» дыры голодали кап перпетуальными
   MISS-GET. Уже снятые их файлы остаются лежать — этап 4 (GC) не должен
   опознать их сиротами (митинг жив в meetings_year_*). Оговорка: этап,
   отменённый после отгонявшихся сессий, теряет только хвосты добора.
10. Pit-heal — только сезоны ≥2026 (регрессия stop_duration началась с
   Венгрии-2026; архив 2023–25 источник не дозаполняет — замер 07.09: из
   49 больных питов 40 «вечных» 2023–25 и 9 живых 2026). Больной пит —
   НЕ неполнота митинга (полнота = только дыры/устарелость файлов);
   лечение — отдельный канал healMeetingPits с прежним капом 6.
   «Заморожен и полон → пропуск» покрывает 73/87 замороженных митингов
   (с питом в полноте было 36/90).
11. Пустой race_control (решение на этап 3): пустых фактов не бывает —
   сессия без классифицированных событий пишется строкой-маркером с
   parser, иначе пустой массив нечем версионировать пер-строчно и бамп
   парсера не доехал бы до него никогда.

**Этапы:** 0 — openf1facts.ts (реестр/оракул/сторожа/предполёт/добор) —

## 2. Прогноз погоды в витрине (фаза B)

Два семейства + координаты: `<серия>/forecast/<eventId>.json` (форма
hourly 1:1 с клиентским HourlyForecast, режимы forecast/archive/typical
считает БЭК, seal по полноте, kept-previous) и `weather/now.json` (один
файл, 41 трасса, мини-hourly −3ч…+6ч). Координаты — `coord` в
refs/matching.json (перенос из словаря клиента с РУЧНЫМ ревью двух
пространств ключей: canonicalName ↔ asset-slug). Продьюсер
`forecast.ts` в ежечасном snapshot (typical — только в суточном слоте);
бюджет ~1300 запросов/сутки при лимите 10k. Клиент: ForecastSource
mirror-first, фолбэк на прямой Open-Meteo до 0.6.6; Open-Meteo —
CC-BY, атрибуция в About. Открытый вопрос: глубокий архив (WEC 2011+)
— рекомендация: разовый ручной бэкфилл.
